  LoRA が元の重みを固定して差分を学ぶこと、QLoRA が 4bit 圧縮を加えることを本文で確認できた。
- `--trace` で見えたツール呼び出し（ツール名・引数・回数、Tree でたどった目次など）：
  - ベクトル検索：`search_materials` を 1 回（query='LoRA 固定 QLoRA 追加'）
  - Tree：`browse_tree` を 4 回（{} → 'lec02-main' → 'lec02-main-s045' → 'lec02-main-p052'）

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  今回の質問は全方式で正答し、根拠不足の例は作れなかった。全文投入は入力が 117,025 トークンと大きく、
  必要な p.52 が埋もれやすい条件だったが、今回は引用できていた。
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  基本のベクトル検索を採用したい。費用が $0.0013 と最も小さく、引用も p.51・p.52 と十分だった。

- 気づき・疑問：
  - 費用はほぼ入力トークンに比例する。全文投入は検索の約 27 倍の費用で、時間はむしろ短かった。
    速さと安さは別物で、測る指標を分けて見る必要がある。
  - Tree は 4 回のツール呼び出しで正しいページに到達し、経路を追える点は利点だが、応答 5 回で最も遅い。
  - Graph は 1 回の呼び出しで前後ページも含めて返し、入力 5,775 トークンで正答した。
  - 今回の質問は単一ページ（p.52）で根拠がそろう易しい例。複数ページにまたがる質問では結果が変わる可能性がある。

## 宿題

- 取り組んだレベル：基礎

- やったこと：
  `app/config.py` の `RAG_TOP_K` を 5 → 3 に変更した。他は変えていない。
  同じ質問（LoRA/QLoRA）を `--trace` 付きで前後 1 回ずつ実行して比べた。

- 結果：

  | 項目 | 変更前（5） | 変更後（3） |
  |---|---|---|
  | 検索語 | 'LoRA QLoRA 固定 学習 第2回' | 'LoRA 固定 QLoRA 追加' |
  | 返ったページ数 | 5 | 3 |
  | 回答 | LoRA=重み固定・差分学習、QLoRA=4bit 付加（正答） | 同内容で正答 |
  | 引用 | 第2回 p.51, p.52 | 第2回 p.51, p.52 |
  | 入力トークン | 3,037 | 2,079（−31.5%） |
  | 出力トークン | 161 | 171 |
  | 応答時間（秒） | 13.55 | 3.01 |
  | 推定費用（USD） | $0.001314 | $0.001051（−20%） |

- 気づき・疑問：
  - 件数を 5 → 3 に減らしても、必要な根拠（第2回 p.51, p.52）は残り、回答も正しいままだった。
    5 件のうち 2 件は今回の質問には不要で、入力トークンが 31%、費用が 20% 減った。
  - 検索語は実行ごとに変わった（'LoRA QLoRA 固定 学習 第2回' → 'LoRA 固定 QLoRA 追加'）。
    生成が確率的なので、件数の効果だけを切り出すには、検索語を固定するか複数回試す必要がある。
  - 応答時間は 13.55 → 3.01 秒と大きく縮んだが、初回は埋め込みやモデル取得で遅くなることがある。
    時間の差を件数の効果と断定せず、トークン数と費用を主な指標にした。
  - 件数を減らしすぎると根拠が落ちる可能性がある。章をまたぐ質問など、根拠が複数ページに散る質問でも確かめる必要がある。
