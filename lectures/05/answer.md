## 宿題

- 取り組んだレベル：基礎

- やったこと：
  `app/config.py` の `RAG_TOP_K` を 5 → 3 に変更した。他は変えていない。
  同じ質問（LoRA/QLoRA）を `--trace` 付きで前後 1 回ずつ実行して比べた。

- 結果：

  | 項目 | 変更前（5） | 変更後（3） |
  |---|---|---|
  | 検索語 | 'LoRA QLoRA 固定 学習 第2回' | 'LoRA 固定 QLoRA 追加' |
  | 返ったページ数 | 5 | 3 |
  | 回答 | LoRA=重み固定・差分学習、QLoRA=4bit 付加（正答） | 同内容で正答 |
  | 引用 | 第2回 p.51, p.52 | 第2回 p.51, p.52 |
  | 入力トークン | 3,037 | 2,079（−31.5%） |
  | 出力トークン | 161 | 171 |
  | 応答時間（秒） | 13.55 | 3.01 |
  | 推定費用（USD） | $0.001314 | $0.001051（−20%） |

- 気づき・疑問：
  - 件数を 5 → 3 に減らしても、必要な根拠（第2回 p.51, p.52）は残り、回答も正しいままだった。
    5 件のうち 2 件は今回の質問には不要で、入力トークンが 31%、費用が 20% 減った。
  - 検索語は実行ごとに変わった（'LoRA QLoRA 固定 学習 第2回' → 'LoRA 固定 QLoRA 追加'）。
    生成が確率的なので、件数の効果だけを切り出すには、検索語を固定するか複数回試す必要がある。
  - 応答時間は 13.55 → 3.01 秒と大きく縮んだが、初回は埋め込みやモデル取得で遅くなることがある。
    時間の差を件数の効果と断定せず、トークン数と費用を主な指標にした。
  - 件数を減らしすぎると根拠が落ちる可能性がある。章をまたぐ質問など、根拠が複数ページに散る質問でも確かめる必要がある。
